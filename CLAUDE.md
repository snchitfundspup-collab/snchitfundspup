# SN Chit Funds & SN Traders — project notes

These notes are shared between the office and home computers through git, so any Claude session starts with the same knowledge. Keep them up to date when a rule or setup changes. The Laravel Boost block further down is regenerated by Boost — put project notes here, above it.

## What the app is

One Laravel 13 / PHP 8.4 app (Blade, per-page CSS/JS through Vite, DomPDF) running two businesses owned by two partners, **Narayanan** and **Sathiya**:

- **SN Chit Funds** — chit groups, members (seats), monthly collection, draws/payouts.
- **SN Traders** — rice buying and selling, in **whole bags only** (no kg on screen).

Customers are **shared** by both businesses; everything else (transactions, expenses, settlements) is separate. `App\Http\Middleware\SetBusinessContext` decides the business from the route (`traders.*` → Traders; `customers.*`, `password.*`, `usage.*` keep the last one; everything else → Chit Funds) and shares `$business` with every view (header, menu, footer, page titles). The dashboard of each business has a button to switch to the other.

Only staff sign in (`users` table, username + password; seeded by `AdminUserSeeder`: `narayanan`, `sathiya`). Customers cannot sign in yet — a customer page is planned.

## Business rules (decided by the owners — do not change without asking)

**Chit group months.** A group month runs from the group's start date, never the calendar month: a group starting 15 Sep has month 1 = 15 Sep – 14 Oct. Use `ChitGroup::currentMonthNumber()`, `dateForMonth()`, `monthEndDate()`, `monthPeriodLabel()`; never calendar arithmetic. Show a group month as its date range ("15 Sep – 14 Oct 2026"). Dashboard "collected today / this month" totals are calendar-based and are a different thing.

**Collection (Due / Pending).**
- A month falls due on its start date (month 1 due 15 Sep, month 2 due 15 Oct).
- **Due** from the 1st of the due date's calendar month until the due date (1–15 Sep). Before that **Upcoming** (not shown by default). From the day after the due date **Pending**.
- Once a member makes a partial payment towards a month, that month is Due straight away.
- Months are collected one at a time: only the oldest unpaid month shows; the next appears when it is fully paid. Several passed due dates → all those months are Pending.
- Month 1 must be paid in full; partial / daily payments are allowed from month 2.
- The admin picks the month; the amount can never exceed that month's balance (no extra, no paying ahead). Logic lives in `ChitGroupMember::collectableMonths()`, `collectionStatus()`, `allocateToMonth()`.
- Collect Payment shows Pending and Due tabs; search finds everyone.

**Colours.** Pending = **red**, Due = **orange**, Part paid = orange. Apply to every badge, ledger cell, report and PDF.

**Customer names.** Wherever a customer's name is shown (screens, prints, PDFs) also show their identification (`customers.remarks`): use `<x-customer-name :customer="$customer" />`; in PDFs write "Name (identification)".

**Design.** Reuse the look of existing components (glass cards, `status-tabs`, `stat-tile`, `ledger-table`, `due-badge-*`, round call button inside the row card). Check how an element already looks elsewhere before adding a new one.

**Expenses (both businesses, separate tables).** Money a partner spends for the business; the partners share it **equally**. Balance Sheet shows paid vs equal share and "who pays whom"; settlements square it up. Traders uses `TraderExpense` / `TraderPartnerSettlement` (subclasses with their own tables) through the same controllers (`ExpenseController`, `BalanceSheetController`, route prefix `traders.`).

**SN Traders.**
- Bags only. Each rice variety has a bag size (label only), **purchase price** and **selling price** per bag. New Sale / New Purchase fill the price; a sale line keeps the purchase price at the time (`trader_sale_items.cost_rate`) for profit. A purchase bill updates the variety's purchase price unless a later-dated bill already set it.
- Stock = bags bought − bags sold. Money not paid at a sale is the customer's credit; receipts pay off the **oldest invoices first** (Customer Dues ageing).
- Purchases are treated as paid when entered (no supplier dues).
- Reports (`Traders\ReportController`): Rice Sales, Profit & Loss (sales − cost of rice sold − expenses, split between partners), Customer Dues (0–30/31–60/61–90/90+ days), Customer Statement finder, Day Book. All print and PDF.

**Usage.** `RecordUsage` middleware logs every full page a signed-in person opens (+ sign-ins) into `usage_logs` (not form posts, live-filter AJAX refreshes, downloads or errors). The Usage page (name menu → Usage) is only for users with `can_view_usage` (Sathiya; gate `view-usage`). Each log also adds to that person's daily count in `usage_daily` (`UsageDaily`). The owners want the detailed log (page, device, IP) kept for **one month only**; daily counts are kept 400 days so the daily/monthly charts and totals survive. Both are pruned daily by `model:prune` (needs the scheduler).

**Lists stay small.** All Payments opens on today only; Traders lists open on this month; wider ranges come through filters.

## Where things are

- Chit Funds: `ChitGroupController`, `ChitGroupMemberController`, `PaymentController` (collect, all payments), `PaymentLedgerController`, `DrawController`, `CustomerStatementController`, `DuesReportController`, `DashboardController`.
- Traders: `app/Http/Controllers/Traders/*`, views `resources/views/traders/*`, PDFs `resources/views/pdf/traders/*`, `resources/css/traders.css`, `resources/js/traders.js`.
- Side menus: `resources/views/components/menu.blade.php` (Chit Funds) and `components/partials/traders-menu.blade.php`; groups use `components/partials/menu-group.blade.php` (items `[route, icon, i18n, label, params?]`).
- Printing: screen print pages extend `layouts/print.blade.php`; PDFs extend `pdf/layout.blade.php`. Both take `$companyName` ('Chit Funds' / 'Traders').
- Translations: English and Tamil strings live in `resources/js/app.js` (two dictionaries). Every visible label has `data-i18n="key"`; add the key to **both** dictionaries.
- Per-page CSS/JS: add new files to `vite.config.js` inputs and load them with `@vite` in the page's `@push`.
- Live filters on list pages come from `resources/js/payments.js` (`#paymentFilterForm`, `#paymentsResults`, `#paymentRanges`); add new filter field names to its list.
- Dates: use `config('app.business_timezone')` (Asia/Kolkata) for "today"; the app timezone is UTC. When counting days between dates, compare plain dates (`Carbon::parse($date->toDateString())`) to avoid off-by-one errors.

## Working on it

- Local: MySQL database `snchitfunds` (`.env`, not in git — each computer has its own). Run `composer run dev` (or `php artisan serve` + `npm run dev`); site at http://localhost:8000. After pulling: `composer install`, `npm install`, `php artisan migrate`, `npm run build`.
- Tests: Pest, SQLite in memory. SQLite stores dates with a time, so filter dates with `whereBetween(col, [$from.' 00:00:00', $to.' 23:59:59'])` or `whereDate`, not `where(col, 'Y-m-d')`. Run `php artisan test --compact` (about 255 tests, all passing).
- Before finishing PHP changes: `vendor/bin/pint --dirty --format agent`; after CSS/JS changes: `npm run build`.
- Commit or push only when asked. Never commit `.env` or `.claude/`.
- On Windows use PowerShell for `php` / `npm`; for multi-line file edits from the shell, write a script file rather than a heredoc.

## Deployment (Laravel Cloud)

- GitHub `snchitfundspup-collab/snchitfundspup`, branch `main`; Laravel Cloud deploys on push (app `snchitfundspup`, environment `production`, Laravel MySQL 8.4).
- After a deploy with new migrations run `php artisan migrate --force` in the Cloud console. Seed admins once with `php artisan db:seed --class=AdminUserSeeder --force` (prints passwords).
- Cost so far is almost all **database storage** (about 5 GB reserved); app and database compute sleep when unused. Plan: once testing ends, create a new database with the smallest storage, migrate, seed, then add real data.
